# Форматы спрайтов `.g16` и `.g17`

`.g17` — это `.g16`, упакованный в сжатый блок движка (заголовок из 9 байт, см.
`g2d.md`; во всех файлах GOG-версии — метод 1, bzip2). Дальше речь только о `.g16`.

В оригинале читаются загрузчиками «Uniform G16 Sprite Loader» (`FUN_01aba290`,
разбор заголовка `FUN_01ab9f00`, блок кадра `FUN_01ab9f90`) и «Non-uniform G16
Sprite Loader» (`FUN_01abaaa0`, `FUN_01aba5d0`, `FUN_01aba630`). Декодер блока —
`FUN_01b0c870`, сборка кадра из плиток — `FUN_01a2…` (строка «Could not cache frame»),
разбор разделов файла — функция с метками `GPAL`/`GINF` (`FUN_01a27…`).

В данных GOG-версии: 400 файлов `GU16` и 98 `GN16` среди `.g16`, 160 и 87 среди `.g17`.

## Разделы

Файл — последовательность разделов `u32 метка, u32 размер (вместе с заголовком), данные`:

| Метка | Содержимое |
|---|---|
| `GU16` / `GN16` | кадры (всегда первым) |
| `GPAL` | палитра: с `+0x422` — 256 записей по 4 байта (R, G, B, не используется); используются старшие 4 бита. С `+0x1A` — ещё одна таблица из 256 записей, назначение неизвестно |
| `GINF` | `u16` по смещению `+0x18` сохраняется движком; остальное (в т. ч. числа с плавающей точкой 100.0, 90.0, 1.0) не изучено |

Смещения блоков ниже отсчитываются от начала основного раздела (он же начало файла).

## `GU16` — все кадры одного размера

| Смещение | Тип | Поле |
|---|---|---|
| 0x00 | char[4] | `GU16` |
| 0x04 | u32 | размер раздела |
| 0x08 | u8 | кадров в блоке |
| 0x09 | u16 | число кадров |
| 0x0B | u16 | ширина кадра |
| 0x0D | u16 | высота кадра |
| 0x0F | u32 | верхняя граница размера распакованного блока |
| 0x13 | u16 | число блоков |
| 0x15 | u32[блоки] | `смещение << 4 \| метод` |
| … | u16[кадры] | назначение неизвестно |

Кадр `i` лежит в блоке `i / кадров_в_блоке`.

## `GN16` — кадры разного размера

| Смещение | Тип | Поле |
|---|---|---|
| 0x00 | char[4] | `GN16` |
| 0x04 | u32 | размер раздела |
| 0x08 | u16 | число кадров |
| 0x0A | u32 | верхняя граница размера распакованного блока |
| 0x0E | u16 | число блоков |
| 0x10 | 6 байт × блоки | `u32 смещение << 4 \| метод`, `u16 кадров в блоке` |
| … | 8 байт × кадры | `u16` (вероятно, число плиток), `u16 ширина`, `u16 высота`, `u16 номер блока` |

Кадры идут по блокам подряд: первый кадр блока — сумма кадров предыдущих блоков.

## Блок

Блок длится до начала следующего (последний — до конца раздела). Первое `u32` —
размер буфера плиток после декодирования (движок выделяет по нему память), затем
данные. Метод: биты 0–1 — сжатие (0 — нет, 2 — LZO1X; 1 — другой распаковщик,
но вместе с ним используемый в данных способ хранения цветов оригиналом не
поддерживается), биты 2–3 — цвета (0 — индексы палитры GPAL, 3 — 12-битные цвета).
В данных встречаются методы 0, 12, 14 и дважды 5 (`most.g16`, `mostshp.g16` — эти
блоки не загрузит и оригинал).

Распакованные данные:

| Смещение | Содержимое |
|---|---|
| 0 | `u32 A`: поток цветов начинается с `4 + A` |
| 4 | `u32 B`: поток альфы начинается с `8 + B` |
| 8 | для каждого кадра блока: `u16 число плиток`, затем описатели плиток `u32` |

Описатель плитки: биты 28–31 — `k`, сторона квадрата `2^k`; биты 12–23 — `x`,
биты 0–11 — `y` (оба знаковые 12-битные, положение в кадре).

Пиксели плиток всех кадров блока идут подряд по строкам. Байт потока альфы
описывает два соседних пикселя: старшая тетрада — левый. Для пикселя с ненулевой
альфой из потока цветов берётся цвет: байт-индекс палитры или `u16` (RGB по 4 бита).
Итог — ARGB4444. Цвета у прозрачных пикселей не хранятся, поэтому для
кадра из середины блока нужно пройти потоки всех предыдущих кадров.

Перекраска в цвет нации (`FUN_01b0c5b0`) в описании не учитывается.
